# 백석대 학우 1:1 랜덤매칭 — 기획서

> 최종 정리: 2026-10-15 · 원본 기획 문서(Claude Docs)와 기획 대화를 바탕으로 정리

백석대 전체 학생을 대상으로, 공강과 상관없이 **하루 한 번 1:1 랜덤 매칭 → 앱 안 익명 채팅(한도 있음) → 둘 다 원하면 카카오톡 ID 교환**으로 이어지는 모바일 웹이다.

## 1. 서비스 정의

| 항목 | 결정 |
| --- | --- |
| 매칭 단위 | 1:1 |
| 시간 조건 | 없음 (공강 매칭 아님) |
| 대상 | 백석대학교 재학생 전체 |
| 구현 | 웹 (모바일 우선 반응형 + PWA) |
| 만남 방식 | 앱 안 채팅 → 둘 다 동의 시 카카오톡 ID 교환 |
| 매칭 목적 | 친구 / 밥친구 / 스터디 중 선택 |

목표 사용자: 신입생·복학생·편입생처럼 아는 사람이 적은 학생, 다른 학과 친구를 사귀고 싶은 학생.

## 2. 사용자 흐름

1. **가입**: 학교 이메일 인증 → 휴대폰 본인인증 → 카카오톡 ID 입력(필수, 교환 전까지 비공개)
2. **신청**: 전날 밤 12시까지 "내일 매칭 참여" + 목적 선택 (매일 자동 참여 옵션)
3. **매칭**: 매일 11:50 서버가 짝을 지어 정오에 "오늘의 학우" 발표 + 푸시
4. **대화**: 24시간 익명 채팅, 각자 메시지 20개까지. 첫 대화용 질문 카드 제공
5. **교환**: 한도 도달(또는 24시간 경과) 후 "교환 / 괜찮아요" 선택. 둘 다 "교환"이면 카카오톡 ID 공개. 한쪽만 고르면 상대는 거절 사실을 모른 채 종료
6. **후기**: 좋았어요 / 별로 / 신고

홀수라 짝이 없으면 다음날 우선 매칭하고 "내일 먼저 매칭해 드릴게요"로 안내한다.

## 3. 기능 (MVP)

| 기능 | 내용 |
| --- | --- |
| 학교 인증 | 백석대 이메일 OTP, 학기마다 재인증 |
| 본인인증 | 포트원 경유 통합 본인인증 (건당 약 40원). 생년월일·성별·CI 해시만 저장 |
| 프로필 | 닉네임, 학과, 학년, 관심사 3~5개, 한 줄 소개, 카카오톡 ID(비공개) |
| 매칭 신청 | 목적 선택, "같은 성별과만" 옵션 |
| 오늘의 학우 | 정오 발표, 공통 관심사를 먼저 보여줌 |
| 익명 채팅 | Supabase Realtime, 각자 20개 / 24시간, 텍스트만 |
| 카톡 ID 교환 | 양쪽 동의 시에만 공개, 공개 전 확인 화면 |
| 신고·차단 | 채팅 상단 버튼, 서로 다른 3명에게 신고되면 자동 정지 |
| 메인 숫자 | "오늘 신청 N명", "이번 주 N쌍이 친구가 됐어요" (성별 구분 없이 총합) |

## 4. 매칭 규칙

- 기본은 **성별 무관 랜덤**, 옵션은 **"같은 성별만"** 하나. **"이성만" 옵션은 없다.**
- 우선순위: 전날 짝 없던 사람 → 같은 목적 → 관심사 겹침 → 무작위
- 제외: 서로의 "같은 성별만" 조건 위반, 차단 관계, 과거에 만난 사람
- 구현: `supabase/migrations/…_init.sql`의 `run_daily_matching()` (pg_cron)

### 성비 불균형(남:여 = 7:3) 대응

| 방식 | 하루 매칭 | 판단 |
| --- | --- | --- |
| 완전 랜덤 | 전원 | 기본값 |
| 이성 매칭 우선 | 여학생 수만큼만 | 비추천: 남학생 대량 매칭 실패, 여학생 부담 |
| "이성만" 옵션 | 여학생 수에 묶임 | 비추천: 대기 길어짐, 이성 매칭 앱으로 인식 |
| 랜덤 + "같은 성별만" | 거의 전원 | **채택** |
| 여학생만 80~90% 남학생과 매칭 | 전원 | 비추천: 남학생 이득은 4~9%p뿐, 여학생 부담 큼, 몰래 조작 |

보완: 하루 1명 구조가 소수 쪽 보호막 · 성비 비공개 · 공통 관심사 먼저 노출 · 여학생 비율 높은 학과 중심 홍보 · 성별별 재참여율 모니터링.
파일럿에서 여학생 5~10명 인터뷰로 확정한다.

## 5. 안전·신뢰

- 학교 이메일 + 휴대폰 본인인증 (위조 성별·중복 가입 방지)
- 실명·학번·전화번호는 상대에게 절대 노출하지 않음
- 교환 전 채팅에서 전화번호·오픈채팅 링크 자동 가림
- 신고·차단, 신고 누적 자동 정지, 교환 후 7일간 "본인 ID가 아니었어요" 신고 가능
- 채팅은 텍스트만 (사진 전송 없음)
- 카카오톡 ID: 암호화 저장, 교환 상대에게만 공개, 탈퇴 즉시 삭제

## 7. 남은 리스크

| 리스크 | 보완 |
| --- | --- |
| 이성 매칭 앱으로 인식 | 목적 선택, 같은 성별 옵션 |
| 매칭돼도 말을 안 걺 | 대화 주제 카드, 한 번에 첫 인사 |
| 불쾌한 대화·스토킹 | 안전 장치 + 채팅을 서비스 안에 둠 |
| 신기함이 끝나면 이탈 | 매일 정오 발표 루틴, 시험 기간 스터디 테마 매칭 |
| 카톡 ID 없음·검색 꺼둠 | 가입 시 "ID 검색 허용" 안내 |
| 남의 카톡 ID 입력 | 교환 후 신고 → 이용 정지 |

## 8. 로드맵과 지표

1. **0단계 수동 검증 (1주)**: 구글폼 신청 → 운영자가 짝지어 메일 발표. 통과 기준: 하루 신청 20명 이상
2. **1단계 MVP (4~6주)**: 인증, 프로필, 신청, 오늘의 학우, 채팅, 교환, 신고·차단, 후기
3. **2단계 전교 오픈 (한 학기)**: 학과·학생회 홍보, 테마 매칭
4. **3단계 확장**: 카카오 채널 알림, 교내 카페 제휴, 후기 기반 매칭 개선

| 지표 | 정의 | 목표 |
| --- | --- | --- |
| 일일 신청자 | 하루 매칭 참여 수 | 50명 이상 |
| 첫 메시지율 | 한 마디라도 주고받은 매칭 비율 | 70% 이상 |
| ID 교환율 | 둘 다 "교환"을 고른 비율 | 20% 이상 |
| 재참여율 | 첫 매칭 후 7일 안 재신청 | 50% 이상 |
| 신고율 | 매칭 100건당 신고 | 1건 미만 |
